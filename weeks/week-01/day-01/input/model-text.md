# Model text: End-to-end pipeline

We have a simple data pipeline. First, we collect data from two places: Kafka events and files in S3. A small Flink job checks the data and writes it to a basic “bronze” table. At night, Airflow makes bigger Parquet files, one folder per day and per customer. We use a schema registry to make sure the data shape is correct. Then a Spark job cleans the data and builds “silver” tables. It also removes duplicates and handles late data. Before we publish, we run a few quality checks. Finally, we create “gold” tables that are easy for business users. Reports read from these tables. Sometimes joins are slow because the data is unbalanced. We reduce this problem with a few tricks. We choose reliability first, even if freshness is a little slower.
