# Week 05 - Session Structure (B1 Level, Speaking-First)

## Standard 90-Minute Session Structure

### 1. Warm-up (10 minutes)
**Activity**: 4-3-2 drill on orchestration design
- **4 minutes**: Explain your orchestration approach
- **3 minutes**: Same topic, more concise
- **2 minutes**: Same topic, most concise
- **1 minute**: Summarize what improved

### 2. Input (15 minutes)
**Activity**: Read orchestration article with transcript
- **Source**: Airflow/Dagster documentation or blog post
- **Focus**: Technical vocabulary and concepts
- **Target**: 8-10 new terms to learn

### 3. Shadowing (15 minutes)
**Activity**: Practice 8-12 key sentences
- **Method**: Slow → Normal → Fast
- **Focus**: Technical terms and linking
- **Target**: Clear pronunciation of orchestration terms

### 4. Vocabulary (10 minutes)
**Activity**: Add chunks to SRS
- **Format**: Multi-word chunks, not single words
- **Examples**: "retry mechanism", "task dependencies", "SLA monitoring"
- **Target**: 8-10 chunks with 2 original examples each

### 5. Speaking Task (25 minutes)
**Activity**: Orchestration design explanation
- **Format**: PREP (Point → Reason → Example → Point)
- **Duration**: 3-4 minutes
- **Focus**: Use new vocabulary and grammar patterns
- **Record**: Practice and record yourself

### 6. Pronunciation (10 minutes)
**Activity**: Micro-drill on technical terms
- **Focus**: Stress patterns in orchestration terms
- **Examples**: "de-FER-ra-ble", "i-DEM-po-tent", "dy-NAM-ic"
- **Method**: 10-20 repetitions

### 7. Log (5 minutes)
**Activity**: Record progress
- **New chunk used**: One phrase you used naturally
- **Error to fix**: One grammar or pronunciation issue
- **Goal for tomorrow**: One specific improvement target

## 60-Minute Session (Recommended)

### 1. Warm-up (8 minutes)
- **4-3-2 drill** on orchestration topic
- **1 minute** reflection

### 2. Input (10 minutes)
- **Read** orchestration article with transcript
- **Identify** 6-8 key sentences

### 3. Shadowing (10 minutes)
- **Practice** 6-8 key sentences
- **Focus** on technical vocabulary

### 4. Chunks/SRS (8 minutes)
- **Add** 6-8 chunks to SRS
- **Include** 2 original examples each

### 5. Speaking Task (18 minutes)
- **PREP** explanation of orchestration design
- **Record** 2-3 minute talk
- **Repeat** once improving flow

### 6. Micro-Pronunciation (3 minutes)
- **One sound** or stress pattern
- **10-20 reps** using shadowing sentences

### 7. Log (3 minutes)
- **One new chunk** used
- **One error** to fix
- **One goal** for tomorrow

## 30-Minute Lite Session

### 3. Speaking Task (12 minutes)

## Speaking Task Options

### Option 1: PREP (Point → Reason → Example → Point)
**Topic**: Why you chose your orchestration approach
- **Point**: "We chose Dagster for our orchestration needs."
- **Reason**: "The reason is that Dagster provides better data lineage."
- **Example**: "For example, when a task fails, we can see which data assets are affected."
- **Point**: "Therefore, Dagster is the right choice for our team."

### Option 2: Problem-Solution-Impact
**Topic**: Retry storm mitigation
- **Problem**: "We had retry storms causing system instability."
- **Solution**: "We implemented exponential backoff and circuit breakers."
- **Impact**: "This reduced retry storms by 85% and improved reliability."

### Option 3: Compare-Contrast-Recommend
**Topic**: Airflow vs Dagster
- **Compare**: "Both provide workflow orchestration but differ in approach."
- **Contrast**: "Airflow uses explicit dependencies, Dagster uses data dependencies."
- **Recommend**: "For our team, I recommend Dagster because of better observability."

## Grammar Integration (B1 Level)

### Relative Clauses
- "A DAG is a workflow that specifies task execution order."
- "Idempotent tasks are operations that produce the same result."
- "SLA monitoring is a system that tracks compliance."

### Reported Speech
- "The team says that data quality has improved."
- "She tells me that the new retry strategy is working well."
- "They report that processing time has decreased by 50%."

### Simple Conditionals
- "If we implement proper testing, we will have fewer issues."
- "Unless we use proper backoff, we'll have retry storms."
- "As long as we follow best practices, our models will be reliable."

### Cleft Sentences (Simple)
- "It was the retry mechanism that prevented the failures."
- "It is the monitoring system that provides visibility."
- "It was the team's approach that improved reliability."

## Success Metrics (B1 Level)

### Fluency
- **Target**: 140-160 WPM in 2-3 minute talk
- **Method**: Record and check once per week

### Chunks
- **Target**: 5+ chunks used naturally in 3-5 minute talk
- **Examples**: "retry mechanism", "task dependencies", "SLA monitoring"

### Complexity
- **Target**: 3+ complex sentences per 2-minute talk
- **Examples**: Relative clauses, reported speech, conditionals

### Intelligibility
- **Target**: 85-90% accuracy on speech-to-text
- **Method**: Record talk and check transcription

### Consistency
- **Target**: 5+ days per week
- **Focus**: Daily practice, even if brief

## Role-Play Personas

### Professional (Default: Senior PM)
**Characteristics**: Tough, concise, interrupts, asks why/how
**Questions**: "Why did you choose this approach?", "How does this handle failures?", "What are the trade-offs?"

### Alternates
- **Finance lead**: Cost pressure, ROI questions
- **Platform lead**: Reliability, performance concerns
- **New hire**: Clarity, learning-focused questions

### Everyday (Default: Curious friend)
**Characteristics**: Warm, interested, shares experiences
**Questions**: "That sounds interesting, can you explain more?", "How does that work in practice?", "What challenges did you face?"

## Feedback Format

After each speaking block, provide:
- **3 reformulations** you can reuse
- **1 pronunciation cue** (stress/linking)
- **1 grammar upgrade** (chunk or structure)

### Example Feedback
**Reformulations**:
1. "We chose this approach because it provides better observability."
2. "The main benefit is that we can track data lineage automatically."
3. "This means we can debug issues much faster."

**Pronunciation Cue**: Stress "ob-SER-va-bil-i-ty" (5 syllables)

**Grammar Upgrade**: Use "which" for non-essential information: "Dagster, which provides data lineage, is ideal for our use case."
